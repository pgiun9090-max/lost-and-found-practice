# 분실물 서비스 명세서 v0.1

## 1. 목적과 범위

이 문서는 교내 분실물 관리 서비스의 개발·검증 기준을 정리한 기준 명세서이다. 원본 고객 요구사항을 분석해 도출했으며, 세부 산출물은 [SRS](SRS_v0.1.md), [RTM](RTM_v0.1.md), [Use Case](UC_v0.1.md)에서 관리한다.

이번 범위는 분실물 조회, 문의 방법 안내, 습득물 등록, 보관·인도 상태 관리이다. 사진 매칭·자동 알림·실제 개인정보·학교 인증 연동은 제외한다. 습득물 접수 장소 안내는 범위가 미정이다.

## 2. 기능 요구사항

| ID | 요구사항 | 검증 기준 |
|---|---|---|
| FR_01 | 사용자는 분실물의 보관 여부를 조회할 수 있어야 한다. | 등록된 물품을 조회하면 보관 여부가 표시된다. |
| FR_02 | 사용자는 보관 중인 분실물의 보관 위치를 조회할 수 있어야 한다. | 보관 중인 물품을 조회하면 등록된 보관 위치가 표시된다. |
| FR_03 | 습득 학생은 습득한 물품을 앱으로 바로 등록할 수 있어야 한다. | 습득 학생이 앱에서 물품 정보를 입력해 새 기록을 저장할 수 있다. |
| FR_04 | 행정 담당자는 분실물 센터로 접수된 습득 물품을 등록할 수 있어야 한다. | 담당자가 센터 접수 물품 정보를 입력해 새 기록을 저장할 수 있다. |
| FR_05 | 행정 담당자는 등록된 분실물의 상태를 보관 중 또는 인도 완료로 기록하고 변경할 수 있어야 한다. | 상태 변경 후 조회 결과에서 변경 상태가 구분되어 표시된다. |
| FR_06 | 사용자는 보관 담당 부서와 문의 방법을 확인할 수 있어야 한다. | 조회 또는 안내 화면에서 담당 부서와 문의 방법이 표시된다. |

## 3. 비기능 요구사항

| ID | 요구사항 | 검증 기준 |
|---|---|---|
| NFR_01 | 학생이 조회·문의·습득물 등록에 필요한 정보를 이해하고 입력하기 쉬운 화면을 제공해야 한다. | 대표 사용자 10명 중 9명 이상이 도움 없이 각 대표 과업을 완료한다. 이 수치는 일반 제안 목표이다. |
| NFR_02 | 행정 담당자의 등록 절차는 업무 부담을 줄일 수 있도록 단순해야 한다. | 일반 제안 목표: 대표 물품 정보 1건을 3분 이내에 등록한다. 측정 환경과 기준 시점은 고객과 확정한다. |
| NFR_03 | 조회 화면에는 개인 휴대전화 번호를 공개하지 않아야 한다. | 조회·안내 화면에서 개인 휴대전화 번호가 0건 표시된다. |
| NFR_04 | 실제 개인정보를 저장하거나 학교 인증 시스템과 연동하지 않고, 가상 데이터만 사용해야 한다. | 실제 개인정보 저장 및 학교 인증 연동이 각각 0건임을 점검한다. |

## 4. 정책

| ID | 정책 | 적용 방법 |
|---|---|---|
| Pol_01 | 개인 휴대전화 번호를 공개하지 않는다. | 개인 번호 대신 담당 부서와 문의 방법을 안내한다. |
| Pol_02 | 가상 데이터만 사용하며 실제 개인정보를 취급하지 않는다. | 화면·저장 데이터·예시 데이터에 실제 개인정보를 사용하지 않는다. |
| Pol_03 | 학교 인증 시스템 연동은 제외한다. | 로그인·학교 계정 인증 연동 기능을 구현하지 않는다. |
| Pol_04 | 사진 등록·비교를 통한 유사 분실물 조회는 제외한다. | 사진 업로드·자동 매칭 기능을 제공하지 않는다. |
| Pol_05 | 사진 매칭 결과 자동 알림은 제외한다. | 수신 정보 등록·자동 발송 기능을 제공하지 않는다. |
| Pol_06 | 분실물 상태는 보관 중과 인도 완료로 구분한다. | 등록·조회 화면에서 두 상태를 별도로 표시한다. |
| Pol_07 | 습득물 등록은 등록 경로와 역할에 따라 구분한다. | 습득 학생은 앱으로 직접 등록하고, 행정 담당자는 센터 접수 물품을 등록한다. |
